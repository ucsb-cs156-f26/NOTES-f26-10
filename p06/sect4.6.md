# Section 4.6: How Big: Small vs. Large Codebases

## Question 1

Most of my earlier CS courses, like CS32, had assignments where I wrote small programs from scratch, usually in just a few files. Since I was the only one reading the code and it only had to pass the tests, I didn't think much about structure or style, which matches what the developers in the paper described. CS156 has been different, because our team works inside an existing codebase that we didn't write. Before adding a feature, I have to read through the existing code and follow the patterns that are already there, which often takes longer than writing the change itself. So my experience is a mix: most of school has been small, stand-alone programs, but CS156 is closer to what the paper says industry is like.

## Question 2

Developers were surprised by how much of their time in industry is spent adding features to large existing codebases instead of writing stand-alone programs. This meant they had to get good at reading and understanding other people's code, which school didn't emphasize much. They also found that integrating libraries, good design, and refactoring were much more important than they expected. Code style also became essential, since developers write code so often that they forget the details, and companies enforce strict style guides to keep a large codebase readable.

## Question 3

The paper suggests giving students an existing system and having them build new features on top of it, so they have to understand the system first. It also suggests putting more emphasis on reading code, integrating libraries, and learning how to refactor and design code with single responsibilities. My own suggestion would be to have students keep working on the same codebase for an entire quarter, or build on code written by previous students, and to require code reviews on pull requests. This would give students more practice reading unfamiliar code and returning to code they've forgotten, which is what working in industry is like.
