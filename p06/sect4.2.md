# section 4.2: When: Short vs. Long Time Spans
Summary by Yongxin Z.

# Question 1
My experience in school is mostly similar to what the paper describes. In most of my CS classes, we write code for assignments, submit them, and then move on to the next one. We rarely need to go back and maintain our old code. Most assignments also focus on writing new code rather than working with an existing codebase. During my internship, I also spent most of my time developing new code for a reinforcement learning project. The only time I really worked with existing source code was when I needed to modify the URLab source code to support my project. I had a few errors while making those changes, but I was able to fix them and get everything working. I didn't spend much time maintaining legacy code. So I would say my experience is a mix. My school experience is similar to what the paper describes, but my internship was different from what most developers in the paper reported because I mainly worked on new code instead of maintaining old code.
# Question 2
One thing developers found surprising was how much time they spent working with legacy code instead of writing new code. In school, students usually start projects from scratch, but in industry, developers often need to understand and modify code written by other people. Some developers also mentioned that even code they wrote themselves could become difficult to understand after a short time.
Another difference was that real-world codebases are often much larger and more complicated than school assignments. Many developers were not prepared for this when they first started working. Some developers also found it difficult to figure out where they should make changes in an existing project without breaking other parts of the code.
# Question 3
I think students should try to work on existing projects instead of always starting from scratch. For example, contributing to open-source projects on GitHub could help students practice reading and understanding code written by others. Students could also go back to their old assignments and try to add new features or fix bugs instead of just leaving them after submission.

Another useful thing would be working on larger group projects that last more than one quarter. This would help students learn how to maintain code over time and collaborate with others. I also think learning Git and writing clear documentation are important because they make it easier for other developers to understand and modify the code. These experiences could help students feel more prepared when they start working in industry.
